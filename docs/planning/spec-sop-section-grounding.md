# 设计：评分标准引用真实的 SOP 章节原文 + 文档要点摘要

负责人要求（2026-10-08，最高优先级）："都需要改成正确，而且取到文档对应的章节"；"要取完整的对应
段落，以及对应的 summary 内容"；"不能是约 600 字"。

## 现状（已在线上和代码里核实）

| 评分标准的来源 | 文档 | 引用的"原文" | 评分时模型看到的 SOP 段落 |
|---|---|---|---|
| 后台「AI 生成评分标准」 | ❌ 不存在的 "SOP Handbook"：线上 `knowledge_base` 为空，检索退回到 mock，返回写死的两条 | ❌ 无 | ❌ 无 |
| rf-CSM 导入程序 | ✅ 真实文档（按 Source Hints 匹配） | ⚠️ 只是出处标签，如 "…SOP section 4.2" | ⚠️ 条目没有页码，取文档**开头**约 600 字（多为封面、目录） |

另外：生成评分标准时交给模型的"SOP 片段"只有文档标题（`checklist_service.py:122`），没有正文。

## 探测结果（本地 26 份真实 SOP，2026-10-08）

- 22 份 PDF 中 17 份有清晰的章节编号（`1 / 2 / 2.1 / 3.1 / 4.2.3 …`）。二级章节（含子条目）中位数
  200–650 字。
- 个别章节很大：Routine Site Monitoring Activities 最大二级章节 49,141 字，Deviation Management 34,227 字，
  Pre-Study Site Visit 15,077 字。
- 5 份 PDF 没有章节编号（Governance Handbook、Study Communication Guidance、Safety Introduction、
  Training Matrix、Country Intelligence 部分）。
- 4 份 docx 没有标题样式也没有编号（两份职位说明、Monitoring Plan、Site Selection Plan）。

## 方案

### 1. SOP 先转成 Markdown，再按章节切分（新表 `sop_sections`）

负责人决定：PDF / Word 先转成 Markdown，按 Markdown 的章节切割和保存。实测（2026-10-08）后按文件类型分开：

| 文件 | 转 Markdown | 章节怎么切 |
|---|---|---|
| PDF | **Azure Document Intelligence** `prebuilt-layout`，`outputContentFormat=markdown`（现有 AI Foundry 资源可直接调用，Entra 认证） | Markdown 标题 + 正文中的编号条目（`4.2`、`4.2.1` 在 DI 输出里是正文，编号单独一行）共同构成章节树：有编号按编号定层级，无编号按 Markdown 标题层级；按 DI 段落角色去掉页眉、页脚、页码（如每页重复的 "STANDARD OPERATING PROCEDURE"） |
| Word | python-docx 自行转换 | 有标题样式按样式；没有时全大写短段落为一级标题、整段加粗短段落为二级标题；表格转 Markdown 表格 |

实测结果：《Clinical Site Management and Monitoring》DI 识别出 1/2/4/5/5.1/5.1.1 等标题，4.2、4.2.1 等 195 个编号条目在正文中；
无编号的《Governance Handbook》识别出 65 个有意义的标题；《Monitoring Plan》docx 没有标题样式，DI 识别不出标题，
但全大写/加粗的标题规律明显。

- 每份文档的 **Markdown 全文也存下来**（`sop_documents.markdown`），管理员能看到切分结果。
- 每个章节一行：`document_id`、`number`（如 `4.2.3`；无编号时为 `§n`）、`title`、`level`、`parent_id`、
  `page_start`、`page_end`、`text`（本章节自身文字，不含子章节）、`order_index`。
- **「完整章节」= 本章节文字 + 全部子章节**，按原文顺序拼接，**不截断**。
- 现有的 `sop_chunks` 保留（覆盖率检查等仍在用），由同一次导入生成。
- 原始文件都在 blob 里，已有的 26 份文档全部重新处理，不需要重新上传。

### 2. 每份 SOP 一份要点摘要（`sop_documents.summary`）

- 导入时由 AI 读取**全文**生成一次：这份 SOP 的目的、适用范围、关键职责和必须遵守的要求。
- 后台 SOP 页面里查看、修改、**审核**。**负责人决定：只有管理员审核通过的摘要才在评分中使用**；未审核
  的摘要不进入评分（评分只用章节原文）。
- 评分时：引用到哪份文档，就附带这份文档已审核的摘要（每份文档只附带一次）。

### 3. 评分条目记录章节号（`checklist_items.source_section`）

- 新字段 `source_section`（如 `4.2`），和 `source_document_id` 一起决定"引用的是哪一段"。
- **报告里显示的引用**：章节号 + 标题（如 "4.2 Regional Clinical Study Manager (rCSM)"），以及从章节里逐字
  摘出的原文；点击打开的是整份文档。
- **评分时交给模型的内容**：这条评分条目对应章节的**完整原文** + 文档摘要。不再有 600 / 3000 字的截断。
- **大小控制不靠截断，靠定位**：引用要落在**最具体的子章节**上（例如 5.3.14，而不是 5）。如果一道题
  所有引用章节加起来仍然超过上限（暂定 60,000 字，约 15,000 token，上线前实测 gpt-5-mini 的耗时后再定），
  不截断，而是记一条警告，并在评分标准编辑器里提示"这道题引用的章节过大，请改为引用更具体的子章节"。

### 4. 给已有的评分标准补上正确的章节（"重新定位引用"）

后台提供「重新定位 SOP 引用」操作，按题库执行，结果写进**草稿**，管理员检查后再发布新版本：

- **rf-CSM**：从出处标签里解析章节号（"section 4.2" → 4.2），直接定位；标签里没有章节号的，在这份文档的
  章节里按维度内容检索最相关的子章节。
- **"SOP Handbook" 这类假引用**：清除，按评分条目内容重新在全部 SOP 里检索；检索不到就留空，如实标明
  "未找到对应 SOP"。
- 每条修改都列出"原引用 → 新引用（文档 / 章节 / 摘出的原文）"，管理员可以逐条接受或修改。

### 5. AI 生成评分标准改为检索我们自己的 SOP 章节

- 去掉检索适配器（Foundry IQ / mock）这条路径。Foundry IQ 只给 Playground 里的 agent 用。
- 按题目内容在 `sop_sections` 中检索（关键词打分，26 份文档、数千个章节规模，不需要另建索引服务）。
  取最相关的若干个章节的**完整原文** + 对应文档摘要，交给模型。
- 模型返回每条评分条目引用的"文档 / 章节 / 原文"。**原文必须逐字出现在该章节里**（忽略空白差异），
  对不上的引用一律丢弃。
- 检索不到相关章节时，如实写"未找到相关 SOP"，不编造出处。

### 6. 和题库版本的关系

章节原文和文档摘要**不存进题库版本**（版本里存的是"文档 ID + 章节号 + 摘出的原文"）。SOP 文档本身
目前不会被修改，只会新增，所以按 ID 和章节号读到的内容是稳定的。重新定位引用后，评分结果会变化，因此
需要**重新发布题库**生成新版本；已经用旧版本进行过的面试不受影响。

## 负责人决定（2026-10-08）

1. 单道题引用章节总量上限先按 60,000 字设计，上线前实测 gpt-5-mini 的评分耗时后再定；超过时不截断，
   只警告并提示改为引用更具体的子章节。
2. 文档摘要必须管理员审核后才用于评分。
3. 「重新定位引用」的结果自动写入草稿，并列出"原引用 → 新引用"，管理员在发布前统一检查。

## 分三个 PR 交付

1. **SOP 转 Markdown + 按章节切分**（新表、重新处理已有 26 份文档、后台 SOP 页面查看章节结构）。不改变评分。
2. **文档要点摘要**（AI 生成、后台审核与修改，审核通过才进入评分）。
3. **评分标准引用正确的章节**（`source_section`、完整章节原文 + 已审核摘要进入评分、重新定位引用、
   AI 生成评分标准改为检索自有章节并校验原文、去掉 mock 检索）。

## 不在本次范围

- 向量检索（embedding）。先用关键词检索，不够用再加。
- SOP 文档本身的版本管理（替换一份 SOP 时保留旧版本）。

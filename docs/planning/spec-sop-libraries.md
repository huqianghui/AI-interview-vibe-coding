# 设计：SOP 文档库——文档归属文档库，题库限定在一个文档库上

负责人提出（2026-10-09）：

> SOP documents 的所有文档都需要归属于某一个主题的文档库，在 SOP 关联的时候，是选定的文档库中的文档进行关联。
> 文档上传之前，需要指定对应的文档库。然后题库是限定在某个对应的文档库上进行的。
> 如果没有（文档库）的，比如一些 demo 的话，就使用 general 的 prompt 来评估。

## 现状（已在代码里核实）

所有 SOP 文档在一个大池子里，凡是要找 SOP 的地方都读整个池子：

| 用到 SOP 的地方 | 现在读什么 |
|---|---|
| AI 生成评分标准（`checklist_service.draft_checklist`） | 全部文档的章节索引（`sop_search.load_index`） |
| 重新定位引用（`sop_citation_service.relocate`） | 全部文档的索引 + 全部文档的摘要（`library()`） |
| 题库主题判断（`bank_is_about_the_sops`） | 全部文档的摘要：由 AI 判断这个题库是不是在考这些 SOP |
| 编辑器里手动引用章节（`CitationEditor`） | 全部文档的下拉列表 |
| 评分（`scoring_service`） | 条目引用的章节原文；提示词固定写 "a fixed checklist derived from an SOP" |

所以一个和 SOP 无关的题库（Demo、Deployment SOP、test-demo01）只能靠 AI 主题判断来避免被引用到无关的临床 SOP 上。这个判断每次运行结果可能不同，不可预期。

## 方案

### 1. 新表 `sop_libraries`，每个文档属于且只属于一个文档库

- `sop_libraries`：`id`、`name`（唯一）、`description`、时间戳。
- `sop_documents.library_id`：非空外键。一个文档只在一个文档库里。
- 文档库可以新建、改名。**有文档的文档库不能删除**（先删除或移走文档）。

### 2. SOP documents 页：先列文档库，点开才展开文档清单；上传在文档库里进行

- 页面先列出所有文档库，每行显示名称、文档数、简介，**默认都收起**。点击一个文档库才展开它的文档清单（现在的文档表格），再点一次收起（负责人，2026-10-09）。
- 上传按钮在展开的文档库里，所以上传前一定已经选定了文档库。上传接口 `POST /admin/sop/documents` 增加必填的 `library_id`；没有就返回 422。
- 页面顶部可以新建文档库；展开的文档库里可以改名。

### 3. 题库绑定一个文档库（可以不绑定）

- `question_banks.sop_library_id`：可空外键。Content 页的题库标题旁边放一个「文档库」下拉框，选项是所有文档库加「不使用 SOP（通用评估）」。
- 绑定是题库草稿的设置，和其他修改一样需要发布才进入新版本。已发布的版本冻结了当时的条目和引用，不受影响。

### 4. 所有 SOP 关联都只在绑定的文档库里进行

| 地方 | 改成 |
|---|---|
| AI 生成评分标准 | 只检索绑定文档库的章节 |
| 重新定位引用 | 只在绑定文档库的索引和摘要里找 |
| 编辑器手动引用 | 文档下拉只列绑定文档库的文档 |
| 保存评分标准（后端校验） | 引用了文档库之外的章节，这条引用直接丢弃（和现在"引用不存在的章节会被丢弃"的处理一致） |

`load_index(db)` 和 `library(db)` 增加 `library_id` 参数。

### 5. 去掉 AI 主题判断（负责人决定）

题库是否引用 SOP 改由绑定决定：没绑定就不引用，绑定了就只在该库里找。删除 `bank_is_about_the_sops`、`TOPIC_PROMPT_MARKER` 以及重新定位里的 `off_topic` 结果。旧的运行报告里已有的 `off_topic` 行照常显示（标签保留）。

### 6. 没有绑定文档库的题库：通用评估

- **AI 生成评分标准**：用通用提示词，按一般面试标准（结构、具体性、结果等）生成条目，不检索 SOP，条目没有引用。
- **评分**：提示词不再说 "derived from an SOP"，改为按评分标准本身判断；没有 SOP 章节部分。报告不显示 SOP 来源。
- **重新定位**：按钮不显示（没有文档库可找），旁边提示「这个题库没有绑定文档库，评估不引用 SOP」。

### 7. 题库换绑文档库：自动清空库外的引用（负责人决定）

换绑（包括改成「不使用 SOP」）时，草稿里所有指向新文档库之外文档的引用（`source_refs`、`source_document_id`、`source_page`、`source_quote`）一并清空。界面提示清空了多少条，需要发布才生效。已发布的版本不变。

### 8. 迁移现有数据（负责人决定）

迁移脚本新建一个文档库，把现有 26 个文档全部放进去。凡是评分标准里引用了任何 SOP 的题库都绑定这个库，其余不绑定。按现在线上的数据，结果是：

- 两个 rf-CSM 题库绑定这个文档库；
- Demo、Deployment SOP Interview、test-demo01 不绑定（这三个题库现在本来就没有任何 SOP 引用），改用通用评估。

为了不把客户名称写进公开仓库，迁移里文档库的名字是通用的 "SOP library"，上线后在界面上改名。

## 待负责人确认

1. **文档能不能在文档库之间移动？** 建议第一版不支持，要换库就删除后重新上传。如果支持移动，引用了它的题库要按第 7 条清空引用。
2. **文档库的名字**：迁移后线上这个库叫什么（例如 "rf-CSM GCO SOPs"）？

## 分三个 PR 交付

1. **文档库**：新表、迁移（第 8 条）、上传必选文档库、SOP documents 页按文档库收起 / 展开、新建、改名。
2. **题库绑定 + 限定范围**：`question_banks.sop_library_id`、Content 页的下拉框、生成 / 重新定位 / 手动引用 / 保存校验都限定在绑定库、换绑清空引用（第 7 条）、去掉主题判断（第 5 条）。
3. **通用评估**：没绑定文档库的题库用通用提示词生成评分标准和评分（第 6 条），用真实模型在本地验证一次 Demo 题库的生成和评分。

## 不在本次范围

- 一个文档同时属于多个文档库。
- 按文档库控制权限（谁能看、谁能改）。
- 面试官 persona 的 Foundry IQ 知识库（那是另一套知识，和评分用的 SOP 文档库无关）。

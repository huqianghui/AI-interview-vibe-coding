# 候选人回答录音

语音面试时，系统会把候选人的回答录下来，供管理员事后复核。

| 项目 | 做法 |
|---|---|
| 录什么 | 只录候选人的**麦克风**，不录数字人的声音。只录真实的候选人面试，后台编辑器里的 Playground 不录 |
| 怎么录 | 麦克风音频本来就经过后端的 Voice Live 代理转发给 Azure，代理在转发的同时保存一份，浏览器**不需要额外上传** |
| 怎么分段 | 每道题一个 WAV 文件（16 kHz 单声道）。每到一道新题，页面通过语音连接发一个标记，代理据此开始这道题的文件。标记只给后端用，**不会发给 Azure**。第一道题开始前的声音不保存，太短（不到 0.5 秒）的片段也不保存 |
| 存在哪里 | 私有 Blob 容器 `recordings`，后端用托管身份写入，权限只限这个容器。数据库表 `interview_recordings` 记录每段录音属于哪场面试、哪道题、多长 |
| 保留多久 | **90 天**。存储账户的生命周期规则 `delete-recordings` 自动删除超过 90 天的录音，不依赖应用本身 |
| 谁能听 | 只有管理员。在「面试结果」里打开一场面试，下方「回答录音」列出每道题的录音，点「播放」后经后端读取（容器是私有的，浏览器拿不到直链）。录音过期后会提示"已删除" |
| 如何告知候选人 | 开始面试前的说明页写明：语音回答会录音以便复核，只录麦克风，90 天后删除 |
| 如何关闭 | 环境变量 `CANDIDATE_AUDIO_RECORDING=false`：不再录音，说明页也不再提示 |
| 出错时 | 录音失败只记日志，**不会影响面试** |

相关代码：`backend/app/services/recording_service.py`、`backend/app/services/voice_live_proxy.py`（转发时保存）、
`backend/app/api/admin_interviews.py`（管理员播放）；基础设施：`infra/azure/modules/storage.bicep`。

为什么不提供一个“整场面试总耗时中位数”？

目前有 4 次完整建连、7 个完整回答、2 条独立评分 operation，但没有覆盖所有阶段、且同一时钟贯穿到底的完整面试样本。实际面试还包含用户思考、说话、回看、问题数量变化和失败恢复。把这些独立样本的中位数相加会产生一个没有真实记录对应的数字。

因此：整场图展示源码确认的顺序和并行关系；分段回放展示真实记录。阶段间没有独立埋点的耗时标为“未独立计时”。

从这条流程看，优化应优先落在哪些地方？

先区分“用户还没点击”和“已经点击却在等”。 停止说话到最终转写的 P50 为 1,047 ms，转写到点击为 688 ms；后者包含用户确认。针对 ASR 收尾、静默策略或界面反馈的调整，需要用新的真实样本评估，不能把用户确认时间全视为可节省的系统开销。

点击后的最大阶段是创建响应到起音，P50 为 631 ms。 它同时包含媒体生成、传输、缓冲和检测，现有数据不足以给每一跳分配毫秒数。后端配对处理 P50 为 56 ms，继续缩短它的收益上限较小；263 ms 的 HTTP 外部等待还需要靠连接、代理与网络证据进一步定位。

保留现有并行，检查可以减少的门控等待与本地队列。 麦克风与 WS、Judge 与正式提交已能重叠。首题重点看配置完成到媒体就绪，评分重点看第 9 个外呼发出前的等待和可选第二批工作。这里列出分析方向，未改变应用行为或运行配置。
